# Script UI and Cooperative Pause Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add session-owned custom script UI, cooperative pause checkpoints, UI callbacks that remain usable while paused, and Stop that interrupts runaway JavaScript.

**Architecture:** Keep one QuickJS runtime per loaded session on a dedicated script thread and continue driving it while paused. Pause controls default-export scheduling; scripts cooperate through `rev.ensureRunning()`. The app control runtime stays responsive and signals QuickJS interruption before enqueueing Stop. A session-owned UI proxy publishes complete rendering snapshots to Unity and receives validated pointer events over the existing WebSocket bridge.

**Tech Stack:** Rust, Tokio, rquickjs 0.12.2, TypeScript/Oxc, C#, BepInEx IL2CPP, Unity uGUI, existing JSON WebSocket packets.

**Spec:** [Script UI and Cooperative Pause Design](../specs/2026-09-28-script-ui-design.md). Read the spec before implementation; it owns the API, defaults, packet shapes, lifecycle rules, and UI behavior.

**Status:** Implementation and automated verification complete on 2026-09-29. Installation/live-game validation and TypeScript compiler checking remain outstanding as recorded below. The earlier proposal for a native QuickJS task-context patch is superseded by cooperative pause.

## Global Constraints

- Use the existing QuickJS runtime and WebSocket bridge; add no runtime fork or dependency.
- Preserve screen-ownership exclusivity and its existing pause/unlock behavior.
- Keep the first UI version to a flat collection of rectangles with optional borders, rounded corners, padding, text, and pointer handlers.
- Preserve the existing `{ uuid, type, payload }` packet envelope.
- Follow existing coding style and never run formatting tools.
- Do not stage, commit, reset, push, or otherwise mutate Git state without an explicit request.
- Implementation and source/build checks are authorized. Installation and live-game actions remain separate.

During execution, preserve unrelated changes, including the currently untracked root `README.md`. `scripts/` is ignored by Git; edit the requested local scripts without changing ignore rules or force-adding them. Use one write owner for shared runtime files; independent source review can run in parallel.

## Review Focus

1. JavaScript spins without yielding during loading, a hook, a default call, or a UI callback: Stop still reaches the engine, cleanup completes, and another script can load. A full command queue or overlapping terminal requests cannot lose cancellation. Owned by Tasks 2 and 5.
2. Pause/resume arrives while execution, checkpoints, or ownership callers are waiting: preserve the invocation, owner, and FIFO position while player input unlocks; prevent missed wakes and duplicate default calls. Owned by Tasks 1-2.
3. A callback awaits while its element is replaced or its session reloads: old events/proxies cannot edit the replacement, and no old continuation issues new work after teardown. Owned by Tasks 4-5.
4. Text edits, handler changes, and reconnect overlap: label revisions must not starve clicks, while stale handler registrations and connection generations are rejected. Owned by Tasks 4-6.
5. Lock state, element geometry, or capture changes between pointer down/up: no mismatched click, synthetic extra click, or input leak to the game. Native/relayed hits use the same rounded box including padding; external borders affect neither layout nor hit area. Owned by Tasks 6-7.
